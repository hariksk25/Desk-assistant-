# Desk Plane Radar (ESP32, 2 screens) - Build Guide

Source model: [MakerWorld 3090203 by Noah Thio](https://makerworld.com/en/models/3090203-desk-plane-radar-esp32-with-2-screens)
Firmware in this folder: `desk_plane_radar.ino` (unified metric/imperial, creator's API keys removed, imperial scaling bug fixed, poll interval made safe for the free OpenSky tier).

## 1. What you are building

| Part of the device | What it does |
|---|---|
| Round 1.28" GC9A01 TFT | Radar view: 3 range rings, N/E/S/W, home marker, one blip per aircraft, selected aircraft in red |
| 0.96" SSD1306 OLED | Selected aircraft: callsign, altitude (ft), speed (kt), heading, distance, aircraft type |
| KY-040 rotary encoder | Rotate = zoom (10/25/50/100/200 km) or step through aircraft. Click = toggle ZOOM / SELECT mode |
| ESP32 DevKit | WiFi to OpenSky every 30 s, hexdb.io lookup for aircraft type, drives both screens |

## 3. Wiring

This is the creator's diagram and README, verified against the pin defines in the sketch. All VCC to 3V3, all GND to GND.

| Component | Pin on module | ESP32 GPIO | Bus |
|---|---|---|---|
| 0.96" OLED | SDA | 21 | I2C (default Wire) |
| 0.96" OLED | SCL | 22 | I2C |
| 0.96" OLED | VCC | 3V3 | |
| 0.96" OLED | GND | GND | |
| Round GC9A01 | SCL (SPI clock) | 18 | VSPI SCK |
| Round GC9A01 | SDA (MOSI) | 23 | VSPI MOSI |
| Round GC9A01 | CS | 5 | |
| Round GC9A01 | DC | 2 | |
| Round GC9A01 | RST | 4 | |
| Round GC9A01 | VCC | 3V3 | |
| Round GC9A01 | GND | GND | |
| KY-040 encoder | CLK | 25 | interrupt |
| KY-040 encoder | DT | 26 | interrupt |
| KY-040 encoder | SW | 27 | interrupt, FALLING |
| KY-040 encoder | + | 3V3 | |
| KY-040 encoder | GND | GND | |

Notes:
- GPIO 2, 4, 5 are ESP32 strapping pins but are fine as outputs here. If the board ever refuses to enter flash mode, unplug the round display's CS/DC wires while uploading, then reconnect.
- The GC9A01 module has no MISO and no backlight pin on most 7-pin boards; nothing to connect there.
- Wire everything on the bench and test before you heat-set inserts or close the case.

## 4. Firmware setup (Arduino IDE 2.x)

| Step | Action |
|---|---|
| 1 | File > Preferences > Additional boards manager URLs: add `https://espressif.github.io/arduino-esp32/package_esp32_index.json` |
| 2 | Tools > Board > Boards Manager: install **esp32 by Espressif Systems** (3.x is fine) |
| 3 | Library Manager, install: **Adafruit GFX Library**, **Adafruit SSD1306**, **GFX Library for Arduino** (by moononournation), **ArduinoJson** (v7 is fine, v6 also works) |
| 4 | Create an OpenSky account at opensky-network.org. Log in > Account > create an **API client**. Copy the client ID and secret. Free tier = 4,000 credits/day, each poll at these ranges costs 1 credit |
| 5 | Open `desk_plane_radar.ino`. Fill in the USER CONFIG block: WiFi SSID/password, HOME_LAT / HOME_LON (right-click your house in Google Maps, copy the two numbers), OpenSky client ID/secret. Leave `UNITS_IMPERIAL 0` for km |
| 6 | Tools > Board: **ESP32 Dev Module**. Port: the USB serial port that appears when you plug the board in (macOS: `/dev/cu.usbserial-*` or `/dev/cu.SLAB_USBtoUART`; install the CP210x or CH340 driver if nothing shows up) |
| 7 | Upload. If it hangs at "Connecting...", hold the BOOT button on the DevKit until upload starts |
| 8 | Tools > Serial Monitor at 115200. You should see `WiFi connected`, `OpenSky token refreshed OK`, `States fetch HTTP code: 200`, `Planes in range: N` |

Default behaviour after boot: 100 km range, ZOOM mode. Click the encoder to switch to SELECT, rotate to walk through aircraft nearest-first. Selected plane is red on the radar and its details are on the OLED.

## 7. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| OLED blank, serial says `SSD1306 init failed` | Module is at 0x3D not 0x3C, or SDA/SCL swapped | Change `0x3C` to `0x3D` in `setup()`, or swap the wires |
| Round screen white or garbage | SCL/SDA (18/23) swapped, or CS/DC/RST wrong | Recheck the SPI table above |
| Round screen colours inverted | IPS flag | Change the `true` in `new Arduino_GC9A01(bus, TFT_RST, 0, true)` to `false` |
| Radar rotated | Rotation param | Change the `0` in the same constructor to 1, 2 or 3 |
| `Token fetch failed, HTTP code: 401` | Wrong OpenSky client ID/secret | Recreate the API client, paste exactly |
| `States fetch HTTP code: 429` | Daily credits exhausted | Keep `POLL_INTERVAL_MS` at 30000 or higher; credits reset daily |
| `States fetch HTTP code: -1` | TLS/heap or WiFi drop | Power from a proper 5V 1A supply, not a laptop hub; check `Free heap` in serial stays above ~60 kB |
| Few or no planes over Bengaluru while FlightRadar24 shows plenty | OpenSky depends on volunteer receivers and coverage over India is thinner than the UK | Try 200 km range first. If it stays sparse, the fetch can be ported to adsb.lol or airplanes.live (free, no key, better Indian coverage). Ask and I'll do that variant |
| Encoder skips or double-steps | Cheap encoder bounce | The quadrature table already filters; if still bad, add 100 nF caps from CLK and DT to GND |
| Upload fails "Failed to connect" | Strapping pins pulled by displays | Hold BOOT during upload, or disconnect the round display while flashing |

## 11. Firmware v4 (framebuffer rendering, 6 apps)

File: `desk_plane_radar_v4.ino`. Same board, partition scheme and libraries as v3. Flash over USB at 115200 or OTA.

Rendering: 8-bit indexed canvas, painted in two bands of 240x120 (29 KB; `CANVAS_BANDS 2`, set 1 on a board with PSRAM) because a full 57 KB framebuffer left only ~46 KB heap and TLS fetches failed with HTTP -1. SPI at 80 MHz on a DMA bus (`USE_DMA 1`), full redraw every frame, free running. Expect 30 to 40 fps, shown bottom-centre of the radar. Aircraft JSON is parsed one object at a time from the stream (no 32 KB document), so a 200 km range fits too. Serial prints `Heap after canvas` at boot and `heap` on every fetch; keep the idle figure above ~70 KB. If the panel shows noise or stays white: set `TFT_SPI_HZ 40000000`, then `USE_DMA 0`. Text is drawn after the sweep and nothing dims with time. Compass words removed; the dial fills the panel with a white north wedge and 30 degree ticks.

Design rule for the two screens: the round display shows the picture or the one big number; the OLED carries the detail and the control hint for whatever is selected. Yellow band (rows 0 to 15 on two-tone panels) holds the headline, blue area the supporting rows.

| App | Round display | OLED | Controls |
|---|---|---|---|
| Radar | Dial, trails, predicted dashed paths, runway 09/27 funnels, icon+count legend (orange arrival, yellow departure, cyan en route), selected flight card | Callsign, N/total, class, route, type, alt, hdg, speed, distance, bearing, landing ETA. Inverts 4 s on new inner-ring traffic | Rotate zoom / step; click toggle ZOOM-SELECT (during an alert: select that aircraft); hold 0.6-2 s filter |
| Clock | 4 faces: digital with daylight and seconds rings, classic analog, nixie, orbital | Time, date, weather, sunrise/sunset, AQI, humidity, UV, aircraft count | Rotate or click: next face |
| Weather | Animated icon (sun rays, cloud drift, rain, snow, lightning, fog), temp, feels, 3 tiles, 12 h sparkline | Temp, feels, condition, 12 h bar chart with min/max, wind, PM2.5, AQI category, UV | none |
| Pomodoro | Preset list (25/5, 50/10, 90/20, custom); running: progress ring, mm:ss, session dots | Preset details, today's sessions and minutes; running: progress bar, session N/4, end time, controls | Rotate pick (custom: set minutes in 5 min steps); click start / pause / resume / skip break; hold 0.6-2 s stop. Long break 15 min after 4 sessions. Buzzer on transitions |
| Markets | Index value, change pill, intraday area chart with previous-close line, next symbol strip | Selected symbol headline, other 3 symbols, day high/low, OPEN/CLOSED, data age | Rotate next symbol; click refresh now |
| WiFi | 2.4 GHz spectrum, one hump per network (channel, RSSI), selected network highlighted | Connected SSID and RSSI, networks on ch 1/6/11/other, least crowded channel | Rotate pick network; click rescan |
| Menu (hold > 2 s anywhere) | 6 apps, selected boxed | App N/6, one-line description | Rotate, click |

Markets data: Yahoo Finance chart endpoint (`query1.finance.yahoo.com/v8/finance/chart/<symbol>?interval=5m&range=1d`), no key, unofficial. Symbols in `MARKET_SYMBOLS` (`^NSEI`, `^BSESN`, `^NSEBANK`, watchlist `RELIANCE.NS`, edit freely). One symbol fetched per pass: every 15 s per symbol while NSE is open (Mon-Fri 09:15 to 15:30 IST) and the Markets app is showing, every 2.5 min otherwise. If Yahoo starts returning 401/429, the serial log shows `Quote ^NSEI HTTP <code>`.

Persisted in NVS: range, source, filter, night, clock face, Pomodoro preset and custom minutes, market symbol.

Fixes found on hardware (v4.2):

| Symptom | Cause | Fix |
|---|---|---|
| Picture rotated 90 degrees, and garbled into two half-height bands after the memory fix | The 6th `Arduino_Canvas_Indexed` constructor argument is the canvas rotation, not the palette mask level; it was 1 | Argument is 0 now. `TFT_ROTATION` (0..3) in the config turns the whole picture if it is not upright in your case |
| `HTTP -1` on every source with heap ~46 KB | TLS needs ~45 KB free; the 57 KB framebuffer and a 32 to 48 KB JSON document did not leave it | Two 240x120 bands, aircraft parsed one object at a time from the stream. Idle heap ~92 KB, ~46 KB during a TLS fetch |
| `adsb.lol HTTP 403` on every cycle while adsb.fi delivered | adsb.lol rate limit (needs >= 15 s between calls) was hit every 10 s because the poll interval followed the active source | Per-source minimum intervals (`SRC_MIN_MS`) and a 1, 2, 4 ... 16 min backoff on 403/429, logged as `adsb.lol rate limited`. A range or source change still fetches at once |
| Rings and arcs start at 9 o'clock | Arduino_GFX measures arc angles from 3 o'clock, the dial math from 12 | `ringArc()` converts; if an arc still starts in the wrong place, change the -90 in `ringArc` |

The 24 h daylight ring on the clock has noon at the top (sun marker climbs left to right), not midnight as in the mockup.

## 13. Firmware v5.2 (scratch arena, 16 apps, 25 additions)

File: `desk_plane_radar_v5.ino` (5,230 lines). Same board, partition scheme and libraries as v5. Flash over USB at 115200, OTA, or from http://deskradar.local/update. Settings from v5/v5.1 are kept (NVS keys unchanged, new ones added).

### How RAM is laid out now

| Pool | What lives there | Size |
|---|---|---|
| Resident, always on | planes, trails, routes, weather (+pollutants, rain), METAR, TAF, SIGMET, destination weather, 7 quotes (price/change/high/low only), news headlines, quakes, alert log, stats, Pomodoro, outages, F1 info, heap/fps history, roaming log | fixed, same as v5 or smaller |
| Scratch arena | one 3.4 KB buffer owned by the app on screen: replay tracks (radar group), remote arrivals board, market chart + heat map + MF NAVs, network latency history, cricket | 3,400 B |
| Two 240x120 canvas bands | the round display framebuffer | 29 KB |

The arena is handed over by `arenaAcquire()` when you enter an app (cleared under the data mutex, the fetch task writes into it only while that group owns it). What this means in use: the market chart, heat map, NAVs, 10 min network graph and cricket scores start empty when you open those apps and fill within one fetch cycle; the replay history is kept while you stay in RADAR / ARRIVALS (home) / APPROACH / REPLAY and starts again after a visit to MARKETS, NETWORK, CRICKET or a remote arrivals board. Everything that raises an alert (traffic, squawk, watch list, go-around, SIGMET, rain, markets, quakes, nudges, timer, alarm) runs on resident state, so a radar alert still appears while the Pomodoro is running. Idle heap should come out ~6 KB above v5.1; `Heap after setup` in the serial log tells.

### Field debugging record (Oct 2026) and what it taught

| Symptom | Real cause | Fix |
|---|---|---|
| Every HTTPS request failed with `HTTP -1 (connection refused)` within one network round trip, DNS fine, WiFi fine, 65 to 83 KB heap free | Not enough heap for mbedTLS: it needs two 16 KB buffers plus ~10 KB context at connect time, and after the first 16 KB buffer a second contiguous 16 KB block has to exist. v4.2 ran at 92 KB idle; v5.2 features and two "fix" builds pushed idle heap to 65 KB | Idle heap back to ~95 KB: JSON documents on the heap (they are freed before any connect), 3 canvas bands of 240x80 (19 KB instead of 29 KB), 3 KB log ring, 40 aircraft. Rule: keep `Heap after setup` above 85 KB and `largest block` above 40 KB |
| Weather and markets never appeared from the first flash | Same cause: their hosts were tried after the heap had already been eaten by the first TLS sessions | Same |
| Round display dim and OLED apparently off at 22:00, back after a power cycle (until NTP sync) | Night mode (22:00 to 07:00). Adafruit `dim(true)` sets OLED contrast to 0, which looks switched off | Night: round 60%, OLED contrast capped at 60/255, never below 12. Night mode on/off/auto on the web page. Transition logged |
| Wrong turns taken on the way | DNS probe (real, but secondary), power supply, RF saturation, heap fragmentation | Logging now carries timestamps, per-request duration, error text, heap and largest block, so the next diagnosis starts from data |

Logging: every outbound request goes through `httpGet()` and logs `[HH:MM:SS] <tag> ok <ms> heap <n>` or `<tag> FAIL <code> <reason> after <ms> heap <n> block <n>`. `/log` holds the last 3 KB. `net check` lines appear after three consecutive feed failures. Serial and /log are identical.

Still parked: the NETWORK app's latency probe (`NET_PROBE_ENABLED 0`) until the feeds have run a full day; REPLAY (`REPLAY_ENABLED 0`).


## v5.3.0: readable OLED

The OLED body text moved from the 6x8 built-in font (21 characters, 5 lines) to the round display's 13 px font F_SM13R (about 18 characters, 3 lines at baselines 29/44/59). Every screen builds a list of lines (`pgAdd`, `pgAddf`, `pgWrap`) and `pgDraw()` shows 3 per page; more than 3 lines becomes pages that auto-advance every `OLED_PAGE_MS` (4.5 s) with a dot column on the right edge. Lines wider than 123 px scroll sideways once (`oledLineB`). The yellow band is unchanged (size-2 title plus two 8 px lines). The news ticker is no longer a permanent 8 px line: `pgNews(n)` adds n headlines as their own pages, word-wrapped. WEATHER keeps its 12 h bar chart as custom page 0 (`pgDraw(1)`). Default arguments for the pager functions live in the forward declarations in p1 because the Arduino prototype generator cannot carry them.

Also in 5.2.2 / 5.3.0: `heapGuardTick()` restarts the board if the largest free block stays under 40 KB for 10 minutes (TLS cannot connect below ~40 KB), and a zero-aircraft 200 response logs the query centre, radius, body length and filter.
